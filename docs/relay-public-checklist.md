## 2. 安全

| # | 项 | 状态 | 说明 |
|---|----|------|------|
| 2.1 | 主码保管 | ✔ | SHA-256 落盘、明文仅显示一次（R1-B）；宿主端 settings 面板输入，不入库明文 |
| 2.2 | 双轨授权独立 | ✔ | 主/子码（运输层）与 Ternimal Token（端到端）互不替代（TC-R2-09 / E2E-02） |
| 2.3 | Token 不明文过中继 | ✔ | 挑战应答 HMAC-SHA256（R4-A，E2E-12：nonce 单次/重放拒/明文拒） |
| 2.4 | E2E 加密（AES-256-GCM） | ▲ | 协议位已交付（R4-B，E2E-13），**默认关**；公开服务建议开启——settings 面板「端到端加密」开关或 `TERNIMAL_RELAY_E2EE=1`（需 https/localhost 安全上下文） |
| 2.5 | 限速与配额 | ✔ | IP+码双重 5 次/分→锁 1 分；每通道并发管道 4；单管道背压 1MB 终止（R1-F） |
| 2.6 | 证书钉扎 | ✔ | 插件对本机 loopback TLS 指纹核对（E2E-05：错指纹→管道中止） |
| 2.7 | 会话/凭据生命周期 | ✔ | Token 每次启动轮换；子码 TTL 1h–7d 可吊销（4009 致命断链，R4-C 对齐后明确提示） |
| 2.8 | 日志脱敏 | ✔ | relay 日志只含通道/客户端短 id 与关闭原因；URL 片段（#S/#T）不进服务端日志 |
| 2.9a | 管理页 /admin | ✔ | scrypt 密码 + 12h 内存会话 + 登录限速；未配置密码时路由 404；verify-relay-admin 10/10（含主码生命周期 B 套件） |
| 2.9 | 插件进程隔离 | ✔ | utilityProcess 子进程；关闭即 OS 级清理（smoke R2H-04 无孤儿进程） |

## 3. 容量与压测（对齐方案书 §3.8：3MB/s 上行、10× 余量）

| # | 项 | 状态 | 说明 |
|---|----|------|------|
| 3.1 | 全链路吞吐 | ✔ | 矩阵 M-05：12MiB/0.6–0.7s ≈ **17–31 MiB/s**（目标 3MiB/s 的 6–10 倍） |
| 3.2 | 慢消费者隔离 | ✔ | M-04：仅背压管道硬终止，健康管道与宿主进程不受影响 |
| 3.3 | 重连矩阵 | ✔ | M-01/02/03：relay 重启/断网/插件被杀三场景自动恢复或明确提示，replay 兜底 |
| 3.4 | 20 会话 × 10min × tc 3MB/s | ✔ | **全量通过** verify-tc-load.mjs：16 交互 4128 次回显 + 3 中度 7.2MB 存活；重度管道背压终止不扩散 |
| 3.5 | 大帧背压发现 | ▲ | 512KiB 合成大帧 + 接收端解析停顿在 1MB 背压阈值下仅 2 帧余量（超设计工况，真实终端帧 KB 级不受影响）。v1.1 提案：阈值可配置或升至 4MB + per-pipe token-bucket |

## 5. 运维

- 健康检查：`GET /health` → `{ok:true, service:'trelay', …}`（监控探活）。
- 流量观测：`GET /api/channels/subcodes`（主码 Bearer）含 joins/bytes 计数（M-05 已验证计数一致）。
- **服务重启语义**：内存 store 清空 → 既有子码全部失效（客户端 4001 明确提示，
  不无限重试）→ 插件自动重注册 + 重新签发子码 + tray 分享链接刷新（M-01 已
  验证恢复路径）。
- 心跳：控制通道 30s ping / 两周期无 pong 收割；管道双向心跳防半开。
- 升级：web bundle 与 app 同版本发布（relay 静态托管同一 dist/web）。
