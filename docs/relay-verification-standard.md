# Ternimal 中继服务器（Relay）— 验收标准文档

> 版本：v1.0
> 上游文档：`docs/relay-design.md`（技术方案书 v0.2）、
> `docs/relay-plan.md`（行动计划书 v1.0）
> 用途：R-M1–R-M4 里程碑验收门与项目最终验收的统一判据。
> 结论只有三种：**通过 / 不通过 / 不适用（需注明理由）**，不允许"基本通过"。

## 1. 验证策略总览

| 层 | 手段 | 覆盖 |
|----|------|------|
| 模块 | 自动化脚本 `scripts/verify-relay.mjs`（假 host/假 client 由 `ws` 扮演） | 控制协议、管道贯通、鉴权、限速、背压、接管 |
| 端到端 | `scripts/smoke-e2e.mjs` 扩展（真实 relay + 真实 Electron + 真实 bash） | 全链路 TLS/管道/会话 |
| 手动用例 | 本文档 §3/§5（含真实外网手机） | 交互体验、生命周期、暴露面 |
| 回归 | 主项目验证标准 §6 清单 + 本文 §6 中继特有回归 | 每里程碑必跑 |
| 稳定性 | soak 测试（§7） | R-M4 验收前一次 |

验证环境基线：

- 内网主机：Deepin 桌面 Linux，仓库就绪（`npm install`，必要时 `npm run rebuild`）
- 公网 VPS：3MB/s 上行，Node ≥18，部署 D-R1 产物 + Caddy（D-R5）；开发期可用
  本机 `--insecure` 实例替代，**但 R-M3 验收门必须至少一次真公网路径**
- 外网客户端 A：手机浏览器，**蜂窝网络（LTE/5G，非内网 Wi-Fi）**，Android
  Chrome 与 iOS Safari 至少其一
- 外网客户端 B：另一外网 PC 浏览器（验证多客户端并发管道）
- 网络模拟：`tc netem`、断 Wi-Fi/蜂窝 30s、`ss -tnp` 观察连接与端口

执行纪律：每个用例记录执行日期、执行人、结果、证据（截图/脚本输出/
`ss`/抓包摘录），汇总入 `docs/test-reports/`。

## 2. 自动化验证脚本

| 脚本 | 验证对象 | 判定 |
|------|----------|------|
| `scripts/verify-relay.mjs` | 主码哈希比对、register/join/offer/pipe 全流程、错码拒绝、挂起超时、重复注册接管、并发上限、背压终止、子码 TTL/吊销、限速锁定、心跳收割、字节透传无损 | 断言全过，退出码 0 |
| `scripts/smoke-e2e.mjs`（扩展） | 真实 relay + 真实 Electron：插件拨号→分享链接→假浏览器双首帧→PTY 交互→关闭插件零残留 | 同上 |

前置：`verify-relay.mjs` 仅依赖 node（≥18）+ 仓库 `node_modules`，自起
`--insecure` relay 实例；`smoke-e2e` 需真实 Electron 环境（同主项目）。

## 3. 里程碑验收门

### 3.1 R-M1 — relay 服务核心

| 用例 | 前置 | 步骤 | 预期 |
|------|------|------|------|
| TC-R1-01 | `relay --add-master` | 检查配置文件与 CLI 输出 | 配置只存 SHA-256 哈希；明文仅签发时显示一次；二次运行不重复显示 |
| TC-R1-02 | 假 host register、假 client join | 任意字节帧双向对发（含二进制、分片） | 管道建立 ≤1s；内容逐字节一致（relay 不解析不改写） |
| TC-R1-03 | 错误主码 register ×6 | 观察响应 | 前 5 次拒绝（BAD_CODE），第 6 次 429 限速锁定，1 分钟后解锁 |
| TC-R1-04 | 过期子码 / 已吊销子码 join | 各试一次 | 拒绝，且不产生 client-offer |
| TC-R1-05 | 假 client join 后 host 不拨 pipe | 等待 10s | 挂起清理，客户端收到明确错误后断开，relay 无残留状态 |
| TC-R1-06 | 同主码二次 register | 新连接注册 | 接管成功；旧控制连接与其全部管道立即收割 |
| TC-R1-07 | 通道已持 4 条活跃管道 | 第 5 个 join | 拒绝（并发上限），既有 4 条不受影响 |
| TC-R1-08 | 单管道客户端停止读取，host 持续灌 >1MB | 观察 bufferedAmount | 该管道终止；host 与其他客户端连接不中断 |
| TC-R1-09 | 子码 API | 签发(带 label/TTL)→列表→吊销→再 join | 各步语义正确；流量统计随 TC-R1-02 递增 |
| TC-R1-10 | `--insecure` 模式 + 静态托管 | 放入 dist/web 后 GET 首页 | 页面与资源可达，路径穿越类请求 403/404 |
| TC-R1-11 | 双端静默 2 个心跳周期 | 不发 pong | relay 主动收割连接与通道状态 |
| TC-R1-12 | — | `node scripts/verify-relay.mjs` | 退出码 0（覆盖 02–08 全矩阵） |

**R-M1 验收门：TC-R1-01～12 全通过。**

### 3.2 R-M2 — Ternimal 插件宿主与接入

| 用例 | 前置 | 步骤 | 预期 |
|------|------|------|------|
| TC-R2-01 | relay 运行 | 设置面板填地址+主码，开启中继 | 拨号成功，tray 显示"中继已连接"；RemoteServer 已绑 127.0.0.1 |
| TC-R2-02 | TC-R2-01 | 点击"生成分享链接" | 链接含 `#S=<子码>&T=<Token>` 片段；tray 二维码同步切换 |
| TC-R2-03 | 中继连接中 | 关闭中继开关 | 子进程退出；`ss -tnp` 无到 relay 的 ESTABLISHED；无新增监听端口 |
| TC-R2-04 | 中继连接中 | 托盘"退出"整个应用 | 插件子进程随主进程死亡，`ps` 无孤儿进程 |
| TC-R2-05 | 设置面板 | 切换"LAN 直连+中继双开"再切回 | 切到 0.0.0.0 有明确暴露面提示；切回恢复 loopback |
| TC-R2-06 | loopback 模式 | 内网另一机器扫描宿主 8443 | 不可达（端口未对外监听） |
| TC-R2-07 | 中继连接中 | `kill -9` 插件子进程 | PluginHost 检测退出，自动重启重连，tray 状态恢复 |
| TC-R2-08 | 中继连接中 | 重启 relay 进程 | 指数退避重连（1s→30s 封顶、带抖动），恢复后通道重建 |
| TC-R2-09 | 脚本持正确子码连 relay | 穿管道后发**错误 Token** 首帧 | auth 被拒（Token 独立性：子码正确也进不了终端）；多次错 Token 触发每连接限速 |
| TC-R2-10 | 真实 Electron + 本机 relay | `node scripts/smoke-e2e.mjs` | 退出码 0 |
| TC-R2-11 | — | 主项目验证标准 §6 本地回归清单全跑 | 全部通过（本地零回归） |

**R-M2 验收门：TC-R2-01～11 全通过。**

启用，避免测试写用户配置）。用例编号 SCENE-R2H-xx：

## 4. 性能基准（R-M2、R-M4 各测一轮）

| 指标 | 测量方法 | 判定线 |
|------|----------|--------|
| 击键回显 RTT（经 relay） | 脚本测 client→relay→host input 与回显 data 的往返分位数（公网路径） | P50 < 80ms，P99 < 250ms |
| join→管道可用时延 | 脚本计时（join 发出到管道首帧可发） | < 1s（不含 TLS 握手） |
| replay 突发 | 1MB 环形缓冲满载后新客户端 attach | 3MB/s 链路 ≤3s 完成，其他会话 RTT 波动 < 50% |
| relay 内存 | 100 条空闲管道挂 30 分钟，记录 relay 进程 RSS | < 200MB，无单调增长 |
| relay CPU | 10 会话重度输出 5 分钟 | 单核 < 60%，无事件循环阻塞（心跳不超时） |
| 透传保真 | 二进制/UTF-8/ANSI 混合帧对发校验和 | 逐字节一致 |

## 5. 真实场景验收（项目级，DoD 第 3 条）

SCENE-R-01 全流程（必须由需求方亲自执行，真公网）：

1. 内网电脑 Ternimal 配置 relay 地址 + 主码，开启中继，生成分享链接发送到
   自己手机；
2. 手机蜂窝网络打开链接，零配置进入终端，接管一个正在运行的真实
   Claude Code 长任务（≥10 分钟）：查看进度、发送追加指令、Esc 中断一次；
3. 途中关闭蜂窝 30 秒再恢复，验证自动重连与输出补齐；
4. 回到内网本地电脑，重开窗口继续操作同一 Claude Code 会话；
5. 关闭中继插件：手机连接即断；内网另一机器扫描确认零暴露。

判定：5 步全部顺畅完成，Claude Code 会话状态始终正确，关闭后内网零残留。

## 6. 回归清单（中继特有，每里程碑必跑）

| # | 项 | 判定 |
|---|----|------|
| 1 | 中继关闭状态下，LAN 远程（主项目能力）完全正常 | 行为与改造前一致 |
| 2 | 中继开启→关闭→再开启，循环 3 次 | 每轮无端口/进程/连接残留 |
| 3 | 中继全程开启，本地窗口全部功能正常 | 主项目验证标准 §6 通过 |
| 4 | relay 停机时应用启动 | 中继进入退避重连，本地与 LAN 功能不受影响 |
| 5 | 配置文件含 relay 段时旧版本行为（如回滚验证） | relay 段被忽略不致崩溃 |

## 7. 稳定性（soak）测试

- 条件：8 小时，relay 与宿主应用持续运行；4 条管道（1 个 Claude Code
  会话、2 个 htop、1 个闲置 shell），客户端每 30 分钟随机断连重连一次；
  每 2 小时采样 relay 与插件子进程 RSS。
- 判定：两进程 RSS 均无单调增长；无未捕获异常退出；全部管道会话存活；
  字节计数与流量统计无异常突增。
- 时机：R-M4 验收门通过后、最终验收前执行一次。

## 8. 缺陷与验收管理

- 缺陷分级：**P0**（阻断核心场景/安全破口/内网暴露）→ 里程碑门禁关闭，
  立即修复；**P1**（功能不可用但有绕行）→ 里程碑内修复或需求方书面接受；
  **P2**（体验瑕疵）→ 记录进二期清单。
- 验收记录模板：用例编号 / 结果 / 证据 / 执行人 / 日期，存
  `docs/test-reports/R{n}-report.md`。
- 最终验收 = 计划书 §8 DoD 五条全部满足 + 本文档 §3–§7 全绿 +
  SCENE-R-01 由需求方签署。
