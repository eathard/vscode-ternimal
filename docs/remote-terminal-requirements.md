# Ternimal 远程多标签终端 — 需求规格

> 版本：v1.0（已与需求方确认）
> 应用场景：远程控制运行在本终端内的 Claude Code 会话

## 1. 背景与目标

Ternimal 目前是单机 Electron 终端（xterm.js + node-pty）。目标：改造为可通过
HTTPS 从外部访问的多标签终端——本地照常使用，远程用浏览器接入后**看到并操控
同一组标签会话**，核心场景是人在离开电脑后继续查看/操控本地正在运行的
Claude Code 长任务。

### 已确认的决策

| 决策点 | 结论 |
|--------|------|
| 接入形态 | 浏览器网页终端（非 API） |
| 会话模型 | 远程与本地**共享同一组标签** |
| 网络环境 | 内网 / VPN 访问 |
| TLS 证书 | 自签名证书，首启自动生成 |
| 宿主运行形态 | Electron 桌面常驻 + 系统托盘，关窗不退出 |
| 一期范围 | 核心版（见 §6 里程碑） |

## 2. 目标架构

```
┌────────────────────── 宿主机：Electron 应用 ──────────────────────┐
│                                                                   │
│  本地窗口 (renderer)              main 进程                        │
│  ┌────────────────┐   IPC(现有)   ┌─────────────────────────────┐ │
│  │ xterm.js UI    │◄────────────►│ SessionRegistry（新增）       │ │
│  │ 标签栏/主题/搜索 │              │  ├─ 会话表: id→Session        │ │
│  └────────────────┘              │  ├─ 每会话环形回放缓冲         │ │
│                                  │  ├─ PtyManager（现有，复用）   │ │
│                                  │  └─ 事件扇出（IPC ∪ WS 客户端）│ │
│                                  │        │                      │ │
│                                  │  RemoteServer（新增）          │ │
│                                  │  ├─ GET /        Web 终端页面  │ │
│                                  │  ├─ POST /auth   令牌鉴权（含   │ │
│                                  │  │   #T= 片段自动交换）          │ │
│                                  │  └─ /ws          会话数据流    │ │
│                                  │  （HTTPS 自签证书）            │ │
│                                  └─────────────────────────────┘ │
└───────────────┬───────────────────────────────────────────────────┘
                │ HTTPS / WSS（内网或 VPN）
      ┌─────────┴─────────┐
      │ 远程浏览器（手机/PC）│
      │ 复用同一套 xterm UI │
      └───────────────────┘
```

核心思想：**会话状态上移**。标签/会话从 renderer 私有状态变为 main 进程的
服务端状态（SessionRegistry），本地窗口和远程浏览器都只是它的客户端。

## 3. 功能需求

### 3.1 会话模型（SessionRegistry）

- FR-1 会话注册表常驻 main 进程：记录每个会话的 id、标题、PTY 句柄、
  环形缓冲、已连接客户端列表。
- FR-2 会话操作：创建（可指定 shell/cwd）、关闭、枚举（含标题）、
  attach / detach。
- FR-3 标签标题同步：复用现有 PTY 标题机制（Claude Code 会动态改标题，
  远程标签栏实时跟随）。
- FR-4 本地与远程共享同一组标签：任一端新建/关闭标签，另一端列表实时更新。

### 3.2 回放与重连

- FR-5 每会话维护环形输出缓冲（默认 1MB，可配置）。远程 attach 时先重放
  缓冲再进入实时流——中途接入、断线重连均能看到 Claude Code 此前输出。
- FR-6 重连：WS 断开后客户端自动重连（指数退避），凭登录态重新 attach，
  以缓冲差量补齐（简化实现：重放全量缓冲亦可接受，一期不做差量）。
- FR-7 心跳：ping/pong（30s 间隔），超时判定断开并 detach。

### 3.3 远程接入（RemoteServer）

- FR-8 HTTPS 服务：托管 Web 终端静态页面；证书首启自动生成自签证书
  （存 userData，并在托盘/页面展示证书指纹供核对）。
- FR-9 WSS 消息协议（JSON 帧）：
  - 客户端→服务端：`auth` / `list` / `attach` / `detach` / `create` /
    `close` / `input` / `resize`
  - 服务端→客户端：`tabs`（列表变更）/ `data` / `exit` / `title` /
    `replay`（缓冲重放）
  - 消息字段尽量与现有 `src/shared/ipcChannels.ts` 的 payload 对齐，
    降低双端协议维护成本。
- FR-10 Web UI 复用现有 renderer 组件（xtermWrapper、tabBar、主题、
  搜索），抽象出传输层接口后打第二个 webpack 入口，产出纯静态文件。

### 3.4 多端共存规则

- FR-11 resize：PTY 只有一个尺寸，采用**最后操作者生效**
  （last-writer-wins）——任一端调整视口即以该端尺寸为准，其余端由 xterm
  自行 reflow/出现滚动条。一期不做服务端虚拟屏适配。
- FR-12 输入：所有已 attach 客户端均可输入，字节流直接混流。文档明确
  提示：Claude Code 对乱序输入敏感，建议同一时间单端操作（只读模式为
  二期功能，协议预留 `readOnly` 字段）。
- FR-13 多设备同时使用同一访问令牌允许（单用户体系）。

### 3.5 认证与安全

- FR-14 动态访问令牌认证：每次启动随机生成 192bit 令牌（env 可覆盖），
  扫码/含令牌链接自动登录，无需手动输入（用户要求，替代原密码方案）；登录
  成功签发 httpOnly cookie 会话，WS 握手时校验，未认证连接一律拒绝。
- FR-15 登录失败限速：同 IP 5 次/分钟，超出锁定 1 分钟。
- FR-16 默认监听 `0.0.0.0:8443`（可配置绑定地址与端口）；文档强调仅限
  内网/VPN 暴露，不直接暴露公网。
- FR-17 托盘菜单可一键查看访问信息（含手机扫码二维码）与重置访问令牌。
- FR-21（迭代新增）Web 端提供**可拖动悬浮软键盘**：Ctrl/Alt/Shift 任意
  组合（一次性粘滞，击键后自动复位）+ Esc/Tab 直发键与 ↑↓←→ 方向键（遵循
  DECCKM 应用光标模式，支持 Ctrl/Alt/Shift 组合修饰），解决移动端无法
  发送 `Ctrl+C` 等组合键的问题；位置可拖动并记忆，切换标签自动清零。

### 3.6 生命周期

- FR-18 关闭本地窗口 → 应用驻留托盘，**PTY 会话全部保活**，远程不受影响。
- FR-19 托盘"退出"→ killAll 并退出（明确语义）；托盘另含"显示窗口"。
- FR-20 配置文件（userData/config.json）：端口、绑定地址、
  证书路径、缓冲大小、开机自启（系统层面配置，二期做 UI）。

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 交互延迟 | 内网 WSS 下按键回显与本地无明显差异（<50ms 感知） |
| 内存 | 回放缓冲每会话默认 1MB，全局可配上限 |
| 弱网 | 心跳检测 + 自动重连 + 缓冲重放，不丢会话 |
| 兼容 | 本地 Electron 使用体验不回归；远程支持现代移动/桌面浏览器 |
| 安全底线 | 明文 HTTP 不可用；令牌仅存内存，证书不出本机配置之外 |

## 5. 现有代码改造点

| 文件 | 改动 |
|------|------|
| `src/main/main.ts` | 关窗行为改托盘驻留；启动 RemoteServer；托盘图标/菜单 |
| `src/main/sessionRegistry.ts`（新增） | 会话表、环形缓冲、attach/detach、事件扇出 |
| `src/main/remoteServer.ts`（新增） | HTTPS + WSS + 静态资源 + 登录/限速 |
| `src/main/ptyManager.ts` | 基本不动，事件改由 Registry 订阅转发 |
| `src/main/ipcHandlers.ts` | 扇出目标从"单窗口"改为 Registry 统一分发（本地 IPC ∪ WS） |
| `src/shared/ipcChannels.ts` | 新增 tabs 列表/变更通道；payload 与 WS 协议对齐 |
| `src/renderer/transport.ts`（新增抽象） | `LocalIpcTransport` / `WebSocketTransport` 同接口 |
| `src/renderer/terminalApp.ts` 等 | 改为依赖 transport 接口，与 Electron API 解耦 |
| `webpack.renderer.config.js` | 双入口：Electron UI 与 Web UI（纯静态产物） |
| `package.json` | 新增依赖 `ws`（node-pty 已是 external，不受影响） |

## 6. 里程碑（核心版 = M1–M4）

- **M1 会话中台**：SessionRegistry + 环形缓冲 + IPC 扇出改造，本地功能
  无回归（纯内部重构，可独立验收）。
- **M2 远程数据通路**：RemoteServer（先 HTTP+WS 裸跑）+ Web UI 双入口，
  内网可用浏览器操控同一组标签。
- **M3 安全**：自签证书 + 令牌鉴权（扫码免输）+ WS 握手校验 + 限速。
- **M4 生命周期**：托盘驻留、关窗保活、配置文件、断线重连打磨。

二期候选（本次不做）：只读观察模式、手机虚拟按键条（Esc/Ctrl/方向键）、
REST API、无头服务器模式、审计日志、多用户。

## 7. 风险与已知限制

1. **resize 冲突**：手机竖屏与桌面宽屏交替使用时画面重排频繁
   （last-writer-wins 的代价）；建议手机横屏使用 Claude Code。
2. **Claude Code TUI 窄屏渲染**：小屏下 TUI 组件可能错位，属 xterm.js
   渲染真实尺寸的固有表现。
3. **双端同时输入混流**可能打乱 Claude Code 的交互状态，一期以使用约定
   规避（单端操作）。
4. **自签证书在 iOS Safari** 的信任流程繁琐；将来可升级 Let's Encrypt
   或走反代。
5. **Electron 需要桌面环境**：本方案明确不支持无显示器服务器（已决策），
  若将来需要，再评估 headless 进程拆分。
